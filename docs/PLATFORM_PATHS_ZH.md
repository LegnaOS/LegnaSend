# 五平台路径约定

更新日期：2026-09-23。适用于 Linux、macOS、iOS、Android、Windows 的工作区、下载、后续 `.ls` 缓存及集成 API。本文说明当前路径基础层，不代表移动存储全部完成。

## 默认目录与原生权限

| 平台 | 原生默认下载位置 | 剩余平台验收 |
| --- | --- | --- |
| Linux | 安装的目录插件按系统／XDG 查询 Downloads；未取得时仅回退到绝对 `$HOME/Downloads` | 自定义 XDG 目录、权限、挂载卷、真实 Linux 读写 |
| macOS | 优先系统 Downloads；位置查询失败时才用绝对 `$HOME/Downloads` | 沙箱／安全作用域授权、移动卷、不同签名配置 |
| Windows | 优先系统已知 Downloads 文件夹，保留重定向；回退绝对 `USERPROFILE/Downloads`，再考虑 `HOMEDRIVE` 与 `HOMEPATH` 组合下的 Downloads | 原生 Windows、UNC／网络盘、长路径、重解析点、离线卷和访问控制 |
| Android | 原生接口返回当前用户／卷的公共 Downloads | 分区存储、SAF 目录树、持久授权与真机；不再猜 `/storage/emulated/0` |
| iOS | 当前应用容器的 `Documents/Downloads`，通过本应用“文件”集成可见 | 真机文件展示、文件提供器选择和安全作用域书签；不是 Safari／iCloud 的公共 Downloads |

用户自选目录原样优先于默认；Android 的 `content://` 不是磁盘路径。解析器只确定位置，不创建目录或写探测文件；已有文件保存层负责创建目标及反馈写入错误。Downloads 不存在时不再悄悄改存 Home。默认目录或缓存目录查询异常会结束当前待接收请求，并显示本地化页内错误；旧查询失败不影响后续会话。iOS 原 Documents 内旧文件不搬迁、不删除。

## 不同路径的处理边界

- 原生根目录遵循宿主文件系统语义。Windows 要有完整盘符根、完整 UNC 共享根或支持的长路径根；拒绝依赖当前盘符的根相对路径和设备命名空间。POSIX 与 Windows 错误编号分别解释。
- 保留 Unicode、百分号、空格和实际拼写。选择后的路径不裁剪、不按 URL 解码、不展开 shell 变量、不全部转小写、不一律替换为 `/`。完整根判断不代替真实权限和目录检查。
- Android 目录树和 Apple 书签引用保留独立源类型。尚未接入或已失效的授权显示明确原因并保持禁用；保存 URI 或绝对路径不等于取得持久权限。
- 网页／API 的相对目录路径统一 `/`，与宿主分隔符无关。目录参数编码一次；返回的文件 ID 和游标视为不透明值。根索引／清单不泄露本地根目录，读取基于已核验目录句柄并保持范围约束。
- 当前目录路由排除内部 `.ls`／`.legnasend*`、后代符号链接／特殊文件及不支持的路径分量，包括反斜线、冒号、控制字符、点分量、末尾空格／点和 Windows 设备名。这个可移植路由命名空间小于宿主文件系统，不能宣称已共享所有合法本地文件名。
- 普通浏览器下载沿用浏览器设定位置；网页中的路径字符串不授予本地写权限。持久受管 `.ls`、平台授权和清理继续单列开发，不把默认位置解析当作缓存系统已完成。
- 原 LocalSend 的端点、文件名字段、握手和传输字节不改；工作区地址和 `.ls` 容器不替换用户原始文件。

## 验证方式

新回归覆盖各平台参数下的默认路径、UNC／长路径、盘符相对拒绝、Android 用户／URI、iOS 容器变化、路径原样保留、错误码、连续接收失败及迟到回调。真实本机目录 HTTP 测试覆盖 Unicode／空格／百分号／井号和范围字节，不二次解码或返回本地根路径。



## Android 接收目录授权与文档身份

2026-09-24：接收设置／当前接收选项选择目录时申请持久读写授权，在保存设置前核验实际已持久化授权和目标目录创建能力。只读分享选择保留只读模式，不强制索取写权限。取消不报错，选择失败显示既有本地化页内弹窗并保留旧设置，页面关闭后的结果不再更新状态。

SAF 接收目录通过新内部平台接口解析：由选择的树根开始，每次读取持久授权和真实文档元数据，查询子目录文档 ID；缺失时使用 createDocument 返回的 ID。文档 ID 是提供器标识，不按目录名猜路径。目录创建结果为空、同名文件／重复名称、自动改名、权限撤销、查询失败、离线或超过扫描预算均失败，不吞错误后继续打开推测 URI。完整分量先校验，每路径最多 128 层，每目录流式扫描最多 100,000 行；不保存全量列表。串行工作线程与 32 项等待队列限制主线程阻塞及并发创建，系统提供器调用本身不是硬超时。

不跨尝试缓存授权或目录映射，重试重新核验；历史使用 createFile 返回的实际文件 URI。外部程序仍可在查询与创建之间修改目录，提供器原子性不作保证；拒绝异常创建结果时不删除可能已有的提供器对象。内部平台接口不是网络 API，原 v2 协议保持不变。


## 接收描述符生命周期

接收尝试在排队任务打开目标前、异步提供器准备后检查原会话身份。取消或服务停止后返回的描述符只关闭，不删除文档。Rust 在等待请求状态前接管所有权，拒绝、参数冲突及未消费的目标通道通过拥有的文件对象释放句柄；原 v2 文件体及同令牌整文件校验重试不变。SAF 文档仍沿用描述符直接写入，完整缓存／发布／清理事务按[实施方案](SAF_RECEIVE_TRANSACTION_PLAN_ZH.md)继续开发。
